# UI Pass 2: Login flow, New Agent dialog, chat gating — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the first-run experience work end to end for a real user: a sign-in link that actually opens (and can be copied), login reachable from File > Settings, no chat input before Claude is logged in, a New Agent dialog that validates the name as you type, opens only once the repository's branches are known, and can start from a folder that is not yet a git repository.

**Architecture:** No new subsystems. One additive protocol change (`workspace.create.init_if_missing`, `repo.inspect` answering for non-repos). Daemon: initialise a folder as a repository on request; seed the sandbox's `.claude.json` so the worktree is trusted. IDE: link detection matches the real `claude.com` sign-in URL; the setup page's terminal moves into the Settings dialog; the transcript composer is gated on the `claude_auth` prerequisite; the New Agent dialog is inspected-before-shown.

**Tech Stack:** Rust (daemon, proto, IDE QObjects), cxx-qt 0.10, Qt 6.9.2 Widgets C++ shell.

**Spec:** `docs/superpowers/specs/2026-09-08-bondsymphonic-ide-design.md` (§7 setup page, §8 transcript, §9 New Agent dialog), `-daemon-design.md` (§4 workspaces, §8.3 credentials and home seeding).

## What the user saw (2026-09-10, first real run)

1. Typing `/login` into the agent chat produced "login is not available in this environment": Claude in `-p` mode cannot log in. The setup terminal's `claude auth login` works (verified through `system.setup_pty`: it prints `Opening browser to sign in… If the browser didn't open, visit: https://claude.com/cai/oauth/authorize?...` and waits for the code), but the IDE never opened the browser because `LINK_PREFIXES` only knows `https://claude.ai/` — the real URL is on `claude.com`.
2. The setup lives under Help; the user expects it under File, in Settings.
3. A workspace name with a space is refused by the daemon after the dialog closes ("workspace name must be a single path-safe word").
4. The New Agent dialog showed before `repo.inspect` answered (it timed out after 30 s on a large `/mnt/c` repository), so the branch list was empty.
5. Creating from a folder that is not a repository is not explained.
6. The daemon log shows `claude: Ignoring 9 permissions.allow entries from .claude/settings.json: this workspace has not been trusted` — the sandbox home's `.claude.json` does not mark the worktree as trusted, so repo-level permissions are ignored.

## Exit criteria

- On the setup terminal, the real sign-in URL opens the browser and can be copied with one click; login is reachable from File > Settings.
- A Claude tab shows a "Log in to Claude Code…" button instead of the composer until `claude_auth` passes; afterwards the composer works without a restart.
- The New Agent dialog refuses a name with whitespace as it is typed, opens only after the repository's branches are loaded, and explains when a folder will be initialised as a repository; creating from such a folder yields a Ready workspace with one commit.
- The daemon log no longer reports "this workspace has not been trusted" for a repo with `.claude/settings.json`.
- Gates green on both hosts; the user tries the flow on the real pair.
